Principles
  • Entrances ≤ 600ms; exits faster.
  • Animate transform/opacity only.
  • Respect prefers-reduced-motion.
  • Loops only for status (pulse/float).
Part 3

Frontend risk review

Grounded in the actual source — every item cites a real file. Severity reflects user/security impact × likelihood. Each card carries a proposed fix.

Critical High Medium Low
R-01

Token refresh is commented out — every 401 logs the user out

src/utils/http.ts:66

The 401 interceptor sets up the refresh queue but the actual refresh call is disabled, so any expired access token drops straight to clearSession() + localStorage.clear(). The session-keep-alive the whole queue exists for never runs. The matching proxy.ts comment ("refreshtoken lỗi là bị lag luôn") confirms this is a live pain point.

// now — refresh never happens
try {
  // await refreshInstance.post("auth/refresh-token");
  processQueue(null);
  return axiosInstance(originalRequest);
}
// fix — actually refresh, then drain queue
try {
  await refreshInstance.post("auth/refresh-token");
  processQueue(null);
  return axiosInstance(originalRequest);
} catch (e) { processQueue(e); /* then clear */ }

Impact: users kicked out mid-session on every token expiry. Fix effort: ~1 line + verify the backend refresh route is wired through the proxy.

R-02

Public-route interceptor swallows errors & returns undefined

src/utils/http.ts:45

On a failed request to a "public" path the interceptor does if (isPublicRoute) return; — returning undefined instead of rejecting. Callers awaiting response.data then read properties of undefined, turning a recoverable network error into a render crash with no error surfaced.

// fix — preserve the rejection so React Query can retry / show error UI
const isPublicRoute = isPublicApi(originalRequest.url);
if (isPublicRoute) return;                       // swallows the error
if (isPublicRoute) return Promise.reject(error); // let callers handle it

Pairs with R-?? the missing error.tsx — even after this fix, an error boundary should catch the throw.

R-03

Middleware crashes on malformed JWT (dev) & mis-guards routes

proxy.ts:38

The catch block reads error.response.data.message — but jwtDecode throws a plain InvalidTokenError with no .response, so the catch itself throws (a second error inside error handling). Separately, the guard only protects /profile and paths ending in /dashboard — deep admin routes like /admin/books/create are not gated at the edge.

// now — catch assumes an axios-shaped error
catch (error: any) {
  if (NODE_ENV === "development") {
    console.log(error.response.data.message); // throws
    header.delete("authorization");
  }
}
// fix — treat any decode failure as "no session"
catch {
  decode = null;
  cookieStore.delete("accessToken");
}
// + widen matcher to /admin/:path*, /staff/:path* …
R-04

Auth/session persisted in localStorage

auth.store.ts:32 · http.ts:75

The Zustand auth store persists user to localStorage and logout does a blanket localStorage.clear(). Tokens already live in cookies (good — the proxy reads accessToken cookie), so user identity in localStorage is XSS-readable and can drift out of sync with the cookie. localStorage.clear() also nukes unrelated keys (cart, language, guest session).

  • Keep tokens in httpOnly cookies only; hydrate user from /auth/me on load.
  • Replace localStorage.clear() with targeted removeItem("auth-storage").
R-05

20 page.tsx are "use client" — Server Components left on the table

grep: 20 / page.tsx

In an App Router app, route entrypoints should default to Server Components and fetch data server-side; marking the page itself "use client" ships the whole subtree to the browser and forfeits streaming + server data. 23 components fetch inside useEffect, which is the client-waterfall pattern RSC is meant to remove.

Pattern: keep page.tsx as a server component that prefetches via React Query's HydrationBoundary, and push "use client" down to the smallest interactive leaf (the existing *DashboardClient.tsx split already does this in places — make it the rule).

R-06

Single global ModalHost eager-loads 14 modals

components/common/Modal/index.tsx

Every visitor — including anonymous storefront users — downloads all 14 admin/staff modals (book editor, goods-receipt, purchase-order, approvals) because ModalHost statically imports them and renders a 14-branch ternary. See the lazy registry proposal for the fix; expect a meaningful storefront bundle drop.

R-07

No error.tsx / Suspense boundaries

app/[locale]/*

Only not-found.tsx exists. A throw in any client query renders Next's unstyled default error screen. Add segment error.tsx, a root global-error.tsx, and per-route loading.tsx — designs provided in Part 1.

R-08

27 : any annotations & 11 stray console.log

grep · src/**

Type-safety leaks (notably in error branches like catch (error: any)) and leftover console.log in http.ts ship to production. Add an ESLint rule (no-console, @typescript-eslint/no-explicit-any) at warn and burn the list down.

R-09

Filenames & types drift from domain spelling

BooksPagiantion · OrderSummany · ModelShow*

Typos baked into paths (BooksPagiantion, OrderSummany, ModelPurchaseOrderDetail vs "Modal", use-search-sematic) make grep/refactor unreliable and read as unpolished. Low risk individually, but they compound. Rename on the next touch of each file.

R-10

Hardcoded UI strings alongside i18n

Header/index.tsx · others

The app is fully wired for next-intl, yet fallbacks like t("header.nav.books") || "Books" and bare aria-label="Orders" leak English into a vi/en product. Move the remaining literals into messages/* so locale switching is complete.

Optimized target

Frontend architecture — proposed shape

Layered data flow
Server Component (page.tsx) · prefetch + Hydrate
HydrationBoundary → client leaf
feature hook (useXQuery) · React Query
service (axios http) → /api proxy
Zustand only for true client state (cart, modal, ui)

Keep the existing features/*/{hooks,services,store,selector} convention — it's clean. The change is where fetching starts (server) and what Zustand holds (UI state, not server cache).

Strengths to keep
  • Consistent feature-folder architecture (hooks/services/store/selector).
  • Clean BFF proxy with hop-by-hop header stripping & cookie passthrough.
  • Design tokens already centralized in globals.css + Radix UI base.
  • i18n routing + role-based dashboard segmentation.
Sequenced roadmap
  1. 1 Fix auth: enable refresh (R-01), stop swallowing errors (R-02), harden middleware (R-03).
  2. 2 Add error.tsx/loading.tsx + move secrets out of localStorage (R-04/07).
  3. 3 Lazy modal registry + push "use client" to leaves (R-05/06).
  4. 4 Lint cleanup, renames, finish i18n (R-08/09/10).
