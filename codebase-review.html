01 · Sơ đồ luồng

Kiến trúc & luồng dữ liệu

Mô hình BFF (Backend-for-Frontend): request đi từ client qua hooks, rồi tới một trong hai đường — route handler app/api/* (proxy, forward cookie) hoặc axios gọi thẳng backend. Token nằm trong httpOnly cookie.

tầng xử lý điểm phân nhánh đường BFF (khuyến nghị) đường gọi trực tiếp
Quan sát chính
  • Hai đường gọi API song song. Cart/auth/admin qua BFF; catalog gọi thẳng backend bằng axios. Không có lý do rõ ràng — nên thống nhất.
  • Feature-sliced nhất quán. Mỗi feature có store/ · selector/ · hooks/ cùng một khuôn — dễ điều hướng.
  • proxy.ts ở root có vẻ mồ côi. Export proxy() + config nhưng không có middleware.ts nào wire vào.
Loại state Nơi lưu Đánh giá
Session user Zustand + localStorage OK
Cart / Wish Zustand (optimistic) OK
Dữ liệu fetch TanStack Query OK
Pagination meta Zustand (catalog) Sai chỗ
Home data Zustand + Query Trùng

03 · Cần xử lý

Vấn đề trọng yếu

Hiệu năng

Lạm dụng "use client" — mất gần hết lợi ích SSR/RSC

app/[locale]/(main)/layout.tsx:1

Toàn bộ nhánh (main) — trang chủ, danh sách, chi tiết sách — đều là client component. Mỗi lần điều hướng là một lần re-hydrate và fetch lại trên client; không SEO cho trang chi tiết, không streaming, không ISR. Đây là thứ một senior phản đối mạnh nhất.

Race condition

Refresh-token có thể gọi nhiều lần đồng thời

utils/http.ts:36–80

Hàng đợi failedQueue chỉ dedupe phần retry, không dedupe chính lời gọi refresh. Hai request 401 gần như đồng thời có thể cùng kích hoạt auth/refresh-token — đúng như comment "bug at admin page" trong proxy.ts. 

let isRefreshing = false;
- if (isRefreshing) { return new Promise(...); }  // cửa sổ check→set không atomic
- isRefreshing = true;
- await refreshInstance.post("auth/refresh-token");  // có thể gọi 2 lần

// Fix: giữ MỘT promise refresh dùng chung cho mọi request đang chờ
+ refreshPromise ??= refreshInstance.post("auth/refresh-token");
+ await refreshPromise;
State placement

Pagination metadata sống trong Zustand thay vì Query

features/catalog/store/catalog.store.ts:11–14

booksPage · booksLimit · booksTotal · booksTotalPages là server/query state nhưng bị nhét vào Zustand, buộc sync tay qua setBooksMeta(). Pagination nên nằm ở URL searchParams (chia sẻ được link) + kết quả lấy từ Query.

Tính nhất quán

services/catalog.service.ts · app/api/cart/route.ts

Cart/auth/admin qua BFF; catalog gọi thẳng backend bằng axios. Người mới vào dự án sẽ bối rối "khi nào dùng cái nào". Chọn một: BFF cho tất cả (nếu cần forward cookie/SSR) hoặc axios cho tất cả.

Cache

features/cart/hooks/index.ts:19

staleTime: 0 khiến refetch mỗi lần mount, triệt tiêu lợi ích cache. Với optimistic update đã có, nên nâng ngang config global (30_000) và dựa vào invalidateQueries sau mutation.

04 · State & Data

Tầng state & dữ liệu

Pattern feature-sliced rất tốt; vấn đề nằm ở ranh giới client state / server state và vài chỗ trùng lặp.

Pattern tốt — giữ nguyên
  • Optimistic + rollback trong mutation cart, kèm invalidateQueries.
  • Query key phân cấp ["catalog","books",page,limit] — invalidate theo nhánh.
  • Hydration flag isHydrated tránh nhấp nháy SSR khi đọc localStorage.
  • Selector tách riêng mỗi feature một file — dễ test.
Cần dọn
  • Method trùng updateQty() và setUpdateCart() giống hệt (cart.store.ts:38–53).
  • Home data hai nơi — vừa Zustand+sessionStorage vừa useHomeQuery(), dễ stale chéo.
  • Selector trả setter tên selectorSession lại trả hàm set — gây hiểu nhầm.
  • Thiếu memo hoá 20 selector catalog không dùng useShallow — re-render thừa.
  • Query key không nhất quán chỗ inline, chỗ constant.

Đề xuất: Query Key Factory

Thay vì rải mảng key khắp nơi, gom về một factory cho mỗi feature — invalidate an toàn theo type, không sợ gõ sai key. 

// features/catalog/query-keys.ts
export const catalogKeys = {
  all:   ["catalog"] as const,
  books: (p: BookQuery) => [...catalogKeys.all, "books", p] as const,
  book:  (slug: string) => [...catalogKeys.all, "book", slug] as const,
};

Comment dày đặc trên từng dòng

fetchHandler.ts và vài component có comment tiếng Việt gần như mỗi dòng, mô tả "cái gì" thay vì "tại sao". Tốt cho việc học nhưng tạo nhiễu. Nên giữ comment cho quyết định khó hiểu, để code tự diễn đạt.

Hiện tại — nhiễu
public status: number; // HTTP status từ BE
public data?: T;       // dữ liệu lỗi
super(message);        // gọi Error constructor
this.status = status;  // lưu status
this.data = data;      // lưu data
Nên — gọn, có chủ đích
export class HttpError<T> extends Error {
  constructor(
    public status: number,
    message: string,
    public data?: T,
  ) { super(message); this.name = "HttpError"; }
}

Type-safety: vài chỗ nên siết

  • order.store.ts:6 — orders: any[] trong khi type Order đã tồn tại; thay bằng Order[].
  • use-admin-book-query-detail.ts:8 — select: (response: any) => response.data nên suy từ type response.
  • Giá tiền lưu string (costPrice · price) — cân nhắc branded type / xử lý decimal rõ ràng cho dữ liệu tài chính.
  • AddressCard nhận t: any, formatAddress: (address: any) — đã có UserAddressData, chỉ cần áp vào.
06 · Bảo mật

Bảo mật

Nền tảng tốt nhờ httpOnly cookie. Các điểm dưới ở mức Low–Medium, nên xử lý nhưng không khẩn cấp.

Vấn đề Mức Vị trí Khuyến nghị
JWT decode không verify chữ ký Medium proxy.ts:36 Chấp nhận được ở middleware, nhưng cần thêm kiểm tra hạn token.
Không kiểm tra token hết hạn Medium proxy.ts Token hết hạn vẫn qua được middleware tới khi logout.
User object trong localStorage Medium auth.store.ts:32 Token thì an toàn, nhưng PII user dạng plaintext — XSS đọc được.
Logout xoá cookie trước khi gọi BE Low app/api/auth/logout/route.ts Nếu BE lỗi, client tưởng đã logout nhưng token còn sống. Đảo thứ tự.
Cookie secure chỉ bật ở prod Low config/cookie.config.ts:3 Rủi ro thấp với localhost; nên mặc định an toàn hơn.
Thiếu error.tsx boundary Low app router Lỗi runtime nổi lên không kiểm soát — thêm error/not-found boundary.
07 · Hành động

Lộ trình cải thiện

Sắp theo tỉ lệ tác động / công sức. Ba việc đầu mang lại thay đổi lớn nhất.

1

Chuyển catalog / detail / home sang Server Components

Fetch trên server, prefetch vào Query cache rồi hydrate. Lấy lại SEO, streaming, ISR cho phần public. Đòn bẩy lớn nhất cho hiệu năng và thứ hạng tìm kiếm.

Tác động ★★★★★ · Công sức ★★★★ · ~1 sprint
2

Vá race condition của refresh-token

Dùng một refreshPromise dùng chung cho mọi request đang chờ. Xử lý dứt điểm bug lag ở trang admin.

Tác động ★★★★ · Công sức ★★ · ~1 ngày
3

Thống nhất một mô hình gọi API

Chọn BFF cho tất cả (khuyến nghị — đã forward cookie & hợp SSR) hoặc axios cho tất cả. Xoá đường còn lại.

Tác động ★★★★ · Công sức ★★★ · ~3 ngày
4

Dời pagination ra URL + Query, gỡ khỏi Zustand

Dùng searchParams cho page/limit (chia sẻ link được), kết quả lấy từ Query. Bỏ setBooksMeta sync tay.

Tác động ★★★ · Công sức ★★ · ~2 ngày
5

Dọn type-safety & log

Khử 28 : any (ưu tiên store & query select), gỡ 21 console.log, bật lại 2 rule ESLint, thêm no-console mức warn cho CI.

Tác động ★★★ · Công sức ★★ · rải rác
6

Áp Query Key Factory + dọn store trùng
